## 4. Migration steps (Shadow PC / UE 5.8)

1. Clone both repos; open `AividoAgentHost.uproject`.
2. Rebuild the `UnrealAgentBridge` plugin (Source in `Plugins/UnrealAgentBridge`) — it provides `UnrealAgentBlueprintLibrary.capture_active_viewport_detailed` and the bridge TCP listener on port **6766** (newline-delimited JSON, `{"type":"python","code":...}`).
3. If textures/materials fail to load (version conversion), re-import:
   - run `python assets/textures/wood_planks/gen_textures_pil.py` (needs Pillow only), import the 3 PNGs to `/Game/AIVIDO/Textures`, recreate `AIVIDO_Mat_WoodTx` (BC→BaseColor, N→Normal, ORM.R→AO, ORM.G→Roughness).
   - re-run the assignment pattern: match slots from `static_mesh.static_materials`, per-actor `set_material` (scripts preserved in `.freebuff/tmp_tx*.py` history).
4. Start backend: `PYTHONPATH=.venv-mac→(Windows venv) python -m app.served` (composition root registers proof routes) or `app.api:app` (routes are also registered in `app/api.py` ~line 107–119). Backend serves UI on **127.0.0.1:8765**.
5. Verify: `GET /api/status` → bridge READY; `GET /api/world/state` → Heidi + 3 workers; map `/Game/AIVIDO_Showcase`.

## 5. UE 5.7→5.8 API deltas already hit (avoid re-triaging)

- Light colors: use `Color` (not `LinearColor`) on light components.
- `spawn_actor_from_object(...)` needs `teleport_physics` arg in `set_actor_transform`/rotation calls.
- Material: `VectorNoise` has no `scale` property; use `Noise` + Position pin; `position` is protected — connect via input pin.
- Mesh import: `EAutomatedAssetImportData` mesh-type enum renamed/dropped — default import type is StaticMesh.
- Material slot names are NOT readable via component `get_material_slot_name` in 5.7 editor python (returns `?`) — read `static_mesh.static_materials` instead.
- FBX import: material slots come from Blender material slot names.

## 6. Known quirks (recorded, not yet fixed)

- **Viewport render-buffer freeze**: on Mac, a background-launched editor instance can render nothing; native capture then returns valid-format but 100%-black PNGs (byte-stable). Fix that works: interactive foreground launch (click into the window) before capture. This session's restart was launched via `open` from a headless shell and stayed black — the bitmap-wall proof is therefore asset-level (assigned+saved), pending one foreground capture.
- `.venv-mac/bin/python` hangs — use system python3.12 with the venv `site-packages` on PYTHONPATH (Pillow), or plain `/opt/local/bin/python3.12` for bridge scripts (stdlib only).
- Capture protocol (when viewport is healthy): frame camera via `set_level_viewport_camera_info` → `editor_set_game_view(True)` → native `capture_active_viewport_detailed()` → verify PNG luma > 0.
